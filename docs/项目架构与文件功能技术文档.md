# 五味字典：项目架构与文件功能

更新：2026-10-10。本文描述当前工作区源码；历史数据核对和产品交接仍见 `docs/整体项目交接.md`。本项目有大量尚未提交的并行修改，文档以实际文件和本轮构建为准。

## 1. 技术架构

应用以 Flutter 构建，Android 为主要交付平台，同时保留 Web/iOS 入口。页面通过 Riverpod 读取状态和仓库；`go_router` 管理导航；领域模型集中在 `features/domain`；离线资源由 `Asset*Repository` 读取。设置、收藏、查询历史和造句记录保存于 SharedPreferences；皮肤包由 Hive CE 管理。

```text
main.dart → app.dart → router.dart / app_shell.dart → features/* 页面
                         ↑                     ↓
                    providers.dart → 仓库接口及 Asset 实现 → assets/data
                                           ↓
                                    domain/models.dart

tool/* 原始资料导入与校验 → assets/data（随安装包发布的离线资源）
```

页面依赖仓库接口，不直接解析大体量字词、诗词资源。`providers.dart` 负责状态和持久化写入排序；导入脚本只在开发阶段执行，应用运行时不依赖 `Aatime` 中的原始 JSON，但笔顺 SVG 和许可文件作为资产随包提供。

## 2. 启动和关键数据流

1. `main.dart` 初始化 Flutter、Hive 和字体后启动 `DictionaryApp`。
2. `app.dart` 装配主题、路由、隐私提示和资源预热；`app_shell.dart` 绘制四栏导航。
3. 路由名在 `app_routes.dart` 统一定义，路径与页面映射在 `router.dart`。
4. `providers.dart` 注入仓库，维护设置、收藏、历史、造句等 Riverpod 控制器。
5. 字、词、文化、诗词页面向仓库请求对象；二进制解码器只解码当前所需记录。

### 诗词库去重（本轮）

`poetry_items_full.wvp` 是唯一打包的诗词正文，含 367,905 条。`poetry_standard_index.wvi` 是 46,005 字节的位图，标识其中 54,659 条属于默认库。索引头为 8 字节签名 `WUWESUB1`、小端全量条数和默认条数，后跟按 WVP 物理记录顺序排列的位。`PoetryCatalog.subset()` 据此生成默认库的随机顺序和原始序号顺序索引；默认库与全量库共享同一份 WVP 字节和有界解码缓存。`AssetPoetryRepository` 对完整资源及默认视图分别做单次异步加载，切换库时不再重复加载文件。

旧默认库 54,659 条与完整库的对应记录已逐条核对所有存储字段，缺失和内容差异均为 0。

旧 `assets/data/poetry_items.wvp` 暂留工作区供历史核对，但已从 `pubspec.yaml` 的资产清单移除，不进入新安装包。以后运行 `tool/import_poetry.dart` 会同时重建完整 WVP 和默认位图。由于默认库现也加载完整 WVP，首次进入诗词页的内存与读盘成本可能高于旧默认库；后续若要进一步优化启动峰值，可采用分片资源和分段索引。

### Android 包交付（本轮）

`build-apk.ps1` 默认使用 `split` 模式，输出 `armeabi-v7a`、`arm64-v8a`、`x86_64` 各自 APK；需要单个通用包时显式传 `-Mode universal`。构建脚本自动递增版本、执行依赖锁校验、检查签名配置、保存 SHA-256 和 JSON manifest。仅有调试签名时，产物适合本地安装验证；正式上架应提供发布密钥并使用 `-RequireReleaseSigning`。安装包体积要按单个目标架构文件衡量，不能将三个文件相加。

本轮 `1.1.0+24` 采用发布签名。对比旧 `1.1.0+22` 通用包 273,509,790 字节：

| 架构 | 新 APK 字节 | 减少字节 | SHA-256 |
|---|---:|---:|---|
| arm64-v8a | 200,205,925 | 73,303,865 | `7386a04f9f34cc1c404f8801a253b7629d4b31573e0b6acec591f6cad4a66a1e` |
| armeabi-v7a | 197,745,617 | 75,764,173 | `02642b77c9fcd05a5d3d19d4c39e85d6724318e1ac55f02add0370daf8d2ab67` |
| x86_64 | 201,624,113 | 71,885,677 | `ce4ddf1273749e74fdaf17bcd814ea7c6106f8bc79825723dd2a3d610947a94f` |

产物及完整构建清单在 `release/apk/five-flavor-dictionary-1.1.0+24-20261010-112439.build.json` 同目录。三种 APK 均已检查包含完整 WVP 与默认位图，且均不包含旧默认 WVP。

## 5. 当前边界与后续重构点

- `culture_pages.dart`、`learning_pages.dart`、`profile_pages.dart` 各承担多个大页面，后续按页面拆分可以缩短编译与评审时的定位成本；拆分需保持路由和状态契约。
- 单字仓库仍以 JSON 为主要资源；与 WVD/WVP 相比，首次加载和对象常驻内存较重。可在做性能基准后迁移到二进制索引。
- 默认诗词库去重降低安装包体积，但当前必须读取完整 WVP。应在真实低内存 Android 设备上测首开时间和峰值内存，必要时改为按段读取。
- 典籍原文、翻译、注释的内容核对由专项流程负责；业务代码重构不要通过改写原始文本来掩盖内容问题。
