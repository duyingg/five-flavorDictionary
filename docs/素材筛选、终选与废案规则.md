# 素材筛选、终选与废案规则

生效日期：2026-09-24
适用范围：字典、诗词、古文、文化页、字形、字体、图片、音频及其他外部素材。
效力：本规则优先于旧调研清单中的“候选”“优先试取”“待核”等描述。旧文档只作为来源索引，不代表准入结论。

## 1. 基本原则

1. **先判能不能用，再研究好不好用。** 权利链不清的资源，不下载大包、不做深度分析、不进入终选。
2. **只认能够证明的事实。** 仓库标签、平台标签、转述、第三方统计和“作者称”不能代替官方许可证、上游来源与实测结果。
3. **用途必须匹配。** 诗词原文、诗句释义、古注、现代白话译文、赏析、训练数据和检索索引是不同资源，不得互相冒充。
4. **镜像不产生新权利。** 抓取站、镜像站、再包装数据集和派生应用不能洗清上游现代译文的版权问题。
5. **不能因为体量大而降低标准。** 一百万条低质量或无授权数据，价值低于一千条权利清楚、内容可靠的数据。
6. **用户的明确决策高于调研文档。** 用户判定终选或废案后，未经用户重新授权不得擅自恢复候选。
7. **下载不等于实装。** 所有外部素材先进入隔离暂存区；只有用户明确下令后才能转换、入库或随 APK 发布。

## 2. 只保留三种正式状态

| 状态 | 含义 | 允许的动作 |
| --- | --- | --- |
| 初筛 | 尚未完成硬门槛核验 | 只允许查看官方说明、许可证、样本和数据结构 |
| 终选 | 已通过硬门槛，值得做最终权利与工程验收 | 可下载样本、做质量抽检和匹配测试；仍不得自动实装 |
| 废案 | 任一硬门槛失败，或用户明确否决 | 停止下载、抽检和推荐；仅保留废案原因与证据 |

禁止使用没有结论的状态词，例如“可能可用”“大概开放”“以后再核”“先抓下来看看”。确实暂时无法确认时，必须归入废案；发现新的决定性证据后，由用户决定是否重开。

## 3. 五道硬门槛

候选必须依次通过下列五道门槛。前一道失败，立即停止，不进入下一道。

### 3.1 用途门槛

- 明确资源究竟提供什么：原文、逐句译文、整诗译文、词语注释、古注、赏析、字形或图片。
- 诗句匹配题、关键词生成诗句、AI 情感标签、主题分类、检索向量，不算诗词白话译文。
- 古注不是现代白话译文；典故说明不是逐句翻译；有“translation”字段不代表字段非空或内容正确。
- 资源不能直接解决当前需求时，立即废案，不因规模大而保留。

### 3.2 权利门槛

必须同时确认：

- 官方来源页面和可保存的许可证文本；
- 数据发布者有权授权相关内容，而不是只给仓库代码授权；
- 是否允许商业使用、应用内展示、离线打包和再次分发；
- 是否允许格式转换、字段拆分、纠错、简繁转换和内容改写；
- 每条现代译文、注释、赏析或图片的上游来源；
- 必须保留的署名、NOTICE、相同方式共享或其他条件。

出现以下任一情况，直接废案：

- “互联网采集”“公开网络爬取”，但没有逐条上游授权；
- 仓库是 MIT、Apache、MPL 或 CC0，但现代内容来自未授权网站；
- 仅限学习、研究、非商业用途；
- 平台许可证与 README、自述或上游条款冲突；
- 购买、调用 API 或允许访问，却没有产品内缓存和再分发权；
- 无许可证，或许可证只覆盖代码而不覆盖数据；
- 无法确认现代译者、注释者或图片权利人。

### 3.3 数据门槛

通过权利门槛后，才允许下载最小样本并实测：

- 真实记录数；
- 目标字段非空数；
- 重复、乱码、控制字符和坏文件数；
- 是否包含原文与译文的稳定对应关系；
- 完整诗数量，而不是句子数、选择题数或总行数；
- 与项目现有数据的可匹配数量。

任何规模数字都必须注明口径。禁止把“总记录数”“句对数”“四个选项”“AI 分析条数”写成“可用译文数”。

### 3.4 质量门槛

所有文本候选必须采用固定随机种子抽样，保存原文、译文、文件位置和评价。

第一轮抽检为 10 条：

- 出现 2 条及以上明显误译，直接废案；
- 出现系统性问题，例如不识别专名、典故、虚词、诗歌意象或长文普遍错配，直接废案；
- 原文与译文被错误断句、错位或截断，先判断能否可靠自动修复；不能证明可修复则废案；
- 只抽名篇、只抽文件开头或人工挑选“看起来最好”的样本，抽检无效。

进入终选后的最终抽检至少覆盖：

- 名篇与冷门篇；
- 短诗与长诗；
- 组诗、异文、同题多作者；
- 典故密集、专名密集和残篇；
- 不同朝代、作者及数据文件。

未经人工审校的机器翻译不得作为正式释义发布。

### 3.5 工程门槛

终选资源必须能够：

- 固定版本、提交号、下载日期和校验值；
- 记录字段级来源与许可证；
- 与现有作品 ID、作者、题名和正文稳定对齐；
- 单独撤回、更新和重新生成；
- 在应用内完整展示署名与许可要求；
- 不因接入而迫使全项目采用不合适的许可证；
- 控制 APK 体积、内存、查询速度和升级成本。

工程上无法隔离来源、无法撤回或无法履行许可条件的资源，仍然废案。

## 4. 诗词译文专用规则

诗词译文候选除五道门槛外，还必须满足：

1. 至少能还原 1000 首完整诗词的原文与白话译文对应关系；句级数据只能作为辅助，不能冒充整诗覆盖。
2. 译文必须真正解释原诗，不得只是主题描述、情感判断、赏析摘要或正确选项。
3. 必须区分诗题、作者、朝代、正文、组诗序号、词牌、异文和译文。
4. 长诗不能按单句独立机器翻译后直接拼接。
5. 对典故、专名、古今词义和省略主语必须有可靠处理。
6. 版权不清的古诗文网站译文及其镜像、抓取库、再包装库一律废案。
7. 非商业、研究用途或禁止演绎的译文，不进入需要统一简体、纠错和重新排版的产品。
8. 没有达到上述条件时，宁可暂时不提供白话译文，也不得填入错误或无权发布的内容。

## 5. 下载和暂存规则

- 只下载已经通过用途与权利门槛的资源，或为核验权利和格式所需的最小样本。
- 大文件下载前必须先查看许可证、文件清单、大小和官方校验值。
- 所有下载放在 `docs/materials_staging/<日期>/`，不得直接放入应用资源目录。
- 同时保存来源 URL、许可证网页或文件、获取日期、版本号和 SHA-256。
- 压缩包内部没有许可证时，必须在记录中明确说明，不能用旁边仓库的许可证自动代替。
- 废案文件原则上不删除，留在隔离区供追溯；不得参与构建、测试数据或应用打包。
- 未经用户指示，不执行格式转换、简繁转换、OCR、入库或 UI 接入。

## 6. 调研报告规则

每次调研先给结论，报告只回答以下问题：

1. 它具体解决什么需求？
2. 官方来源在哪里？
3. 权利是否允许本项目实际使用？
4. 实际可用数量是多少？
5. 随机样本质量如何？
6. 与现有数据库能匹配多少？
7. 结论是初筛、终选还是废案？

报告不得：

- 用大量链接代替结论；
- 重复列出同一上游内容的多个镜像；
- 把尚未实测的宣传数字当结果；
- 在关键权利问题不清时继续做耗时下载和深度分析；
- 用“待核”无限延后否决；
- 把文档中的候选建议当成用户已经批准。

如果需要后续动作，必须写成一个明确、最小、可验收的动作，不能写成笼统的“继续研究”。

## 8. 执行顺序

今后任何外部素材统一按以下顺序处理：

1. 一句话确认用途；
2. 查官方来源和许可证；
3. 查上游内容权利链；
4. 不过门槛立即废案；
5. 通过后只下载最小样本；
6. 固定随机抽检 10 条；
7. 质量通过才统计全量和匹配率；
8. 形成终选结论；
9. 等待用户明确指示；
10. 获准后再实装。

不得倒序执行。
