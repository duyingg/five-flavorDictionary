## 2. 产品定位与运行方式

五味字典是以 Android 手机端为主要场景的离线中文工具，包含：

- 单字、词语和多字查询；
- 拼音、韵脚、部首、笔画、难检字索引；
- 笔顺动画或静态字形展示；
- 今日汉字、猜汉字、多音字、造句便签和小学语文生字学习；
- 标准诗词库、全量诗词库、诗词作者页和原诗详情；
- 诸子百家、典籍、节气、节日、古代称谓等文化内容；
- 简繁切换、字号、侧栏宽度、查询字段和皮肤设置；
- 收藏、查询历史和造句记录的本机保存。

应用无需账号，主要业务数据打包在本地资源中。外部链接仅用于隐私政策、反馈等明确场景。

## 6. 已实现的重要产品契约

### 搜索与字词详情

- 单字输入进入单字详情；2—16 个汉字进入词语详情；过长输入会被拒绝。
- 词语已收录时显示整体读音和释义，随后展示逐字查询内容。
- 未收录词语仍显示各字读音，不能因此阻断逐字详情。
- 词语标题区域按每行 4 个字布局。
- 用户可以分别开关拼音、注音符号、五笔 86、部首、笔画、结构、Unicode 和“字形与笔顺”等字段。
- 右上角首页按钮必须直接清空嵌套路由并回首页。

### 字形与笔顺

- “字形与笔顺”是同一个设置开关。关闭时隐藏整个放大字形/笔顺区域；详情页顶部用于识别词条的普通大字仍保留。
- 开启且有笔顺资源时显示并播放笔顺。
- 开启但没有笔顺资源时，在相同位置显示静态文字大图，不播放伪动画。
- 已取消“超大图占满屏幕”的交互，不要重新加入。
- 四龙合字有专门的组合字形兜底。
- 正文长按应保留系统文字选择和复制能力。

### 每日内容与学习

- 首页每日汉字和“今日汉字”是同一功能，必须来自同一 provider。
- 今日汉字固定为一级字 6 个、二级字 3 个、三级字 1 个。
- 今日汉字按日期固定抽取；词语、成语、诗句使用按类型固定的顺序，再按日序号轮换。资源池有多条时，同一类型连续两天不会展示同一条。
- 同一天重复打开保持当天内容；跨午夜的定时刷新和应用返回前台时的日期核对共同触发重新选择。
- “换一个”按当日顺序切换；首页“每日××”标题右侧的按钮可切换汉字、词语、成语、诗句，并保存偏好。
- 每日词语和成语点击后进入词语整体查询；每日诗句点击后进入原诗页面。
- 造句使用今日汉字中的 6 个一级字，按便签保存，显示年月日时分并支持批量删除。
- 小学语文生字已作为学习页独立子项，数据范围为统编版 12 册写字表。
- 文言文字典以原有单字词库和本机 30 部文献原文、已有译文为检索范围；修改文献正文或译文后需重建 `assets/data/classical_lookup_index.json.gz`，见专项文档。

### 我的与查询历史

- “隐私政策”入口位于“我的 → 关于我们”，隐私政策详情路由保持可用。
- 查询历史页顶部有“清空全部查询历史”按钮，仅在有记录时显示；点击后先确认，再清空本机记录。数据管理页也保留清空入口。

### 诗词与文化

- 诗词标准库和全量库可在数据设置中切换；页面显示的数量必须是实际可浏览数量。
- 搜索范围是当前选中的诗词库。
- 标准库下的“没有找到目标诗?”是列表最后一项，必须滚动到诗词末尾才看到，不是悬浮底栏。
- 点击该提示项跳到诗词库切换开关。
- 有译文的诗保留标记；浏览和搜索规则不要用虚假数量或说明掩盖资源差异。
- 拼音、注释、翻译是三个可同时开启的独立选项。原资源缺少某项时只不显示该项，不能影响另外两项。
- 标点符号不得出现在新行行首；每日诗句按完整分句布局，优先把标点留在行末。
- 文化页和子页面继续支持点击汉字快捷查字。
- 二十四节气是可点击按钮，每个节气进入独立说明页。
- 应用界面已经移除数据来源说明；来源和许可证仅保留在内部元数据、THIRD_PARTY_NOTICES 和开发文档中。

### 注音

- 长文注音优先级：可靠整句 → 已核定通假字语境 → 最长词组 → 单字读音兜底。
- 可靠整句会先将待匹配正文按字符归一为简体，因此简体、繁体和简繁混排正文可以命中同一条来源注音。
- 读音必须显示；找不到可靠版本的内容不能直接隐藏拼音。
- 兜底读音仍有出错可能，不能把整部古籍标为“已完全校准”。逐书覆盖率按应用逐段实际匹配重算，见 `docs/注音校准进度_2026-09-29.md`；旧估算值偏高。

## 7. 状态管理与本机数据

`lib/app/providers.dart` 是当前共享状态中心，包含：

- 字典、词语、每日内容、文化、诗词、简繁和注音仓库；
- 设置、收藏、历史、造句便签控制器；
- 今日汉字、每日内容和每日诗句原诗定位；
- 多音字关卡和无尽模式状态。

SharedPreferences 保存设置、收藏、历史和造句记录；Hive 的 `skin_packages` box 保存导入皮肤。修改 key、模型字段或序列化格式时必须考虑旧版本迁移，不能直接让用户本机数据失效。

## 9. 构建与版本规则

开发环境：

- Flutter 3.47 或兼容版本；
- JDK 17—24，推荐 JDK 21；
- Android SDK / Build-Tools 35；
- Git LFS。

构建入口：`build-apk.ps1`。

```powershell
# 默认通用 APK；成功后构建号 +1
.\build-apk.ps1

# 按 ABI 分包
.\build-apk.ps1 -Mode split

# 同时提升语义版本的 patch
.\build-apk.ps1 -VersionIncrement patch

# 公开发布必须要求 release 签名
.\build-apk.ps1 -RequireReleaseSigning
```

脚本行为：

- 先检查项目结构、Git 冲突、敏感签名文件和并发构建锁；
- 中文路径时用 `subst` 映射短路径；
- 检查锁定依赖；构建脚本不执行格式化、静态分析或自动测试；
- 仅在正式构建阶段递增版本；失败会恢复原 `pubspec.yaml`；
- 生成 APK、SHA-256 文件和 build manifest；
- 默认无私钥时允许 debug 签名，本地安装可用，但不得对外发布。

## 11. 已知风险与技术债

1. `culture_pages.dart` 约 1,808 行，仍同时承载文化首页、文化详情、诗词浏览、诗词详情和节气页面，应按职责拆分，但不能借拆分改变现有交互。
2. `providers.dart` 仍集中管理多个业务域，修改容易影响首页、学习、文化和设置。
3. 单个全量诗词资源约 256 MB，通用 APK 已超过 260 MB；后续若优化体积，应先评估按需资源、分包或外置数据，不得偷偷删减库并显示虚假数量。
4. 不能把应用摘录或部分书的 100% 直接覆盖误称为古籍原书全本完成校准。低覆盖和零覆盖清单见注音进度文档。
5. 《老子》应用正文现有 5,018/5,249 字直接覆盖（95.60%），仍有异文及未命中段落需要与应用正文一致的注音底本；以最新审计为准。
6. 自动拼音网站会误判古今异读、多音字和专名，不能以“公开资源”名义无审查批量导入。
7. 直接运行 Flutter 而不传 `APP_VERSION` 时可能显示旧版本号。
8. 当前已有 APK 是 dirty working tree 构建，后续修改是否已进入该包必须核对构建时间和实际安装行为；不能仅凭存在产物视为最终发布包。
9. 上游 Aatime 原始资料体积大、许可证各异；应用实际资源和下载候选必须分清，候选目录不是自动准入清单。
10. 用户要求界面不展示数据来源，后续只能维护内部来源记录，不能把来源卡片重新加回页面。

3. 按任务阅读对应专项文档，不要把候选资料当成已批准需求。
4. 先只读检查目标功能和资源，再做最小范围修改。
5. 数据、页面重构、构建脚本分别处理，避免一次提交混在一起。
6. 按当前任务要求做必要验证；构建脚本本身不执行测试，交付时说明实际验证范围。
7. 交付时列出修改文件、产物、未完成事项和是否真正执行过测试/构建。

## 14. 不得误报的事项

- 有入口不等于功能已实装；必须同时有数据、页面、路由和异常处理。
- 有少量准确注音不等于整部古籍读音完全正确。
- 能搜索到诗不等于浏览筛选规则正确。
- `flutter analyze` 通过不等于 APK 构建成功。
- 历史 APK 存在不等于它包含当前工作区改动。
- 公开可访问不等于允许打包再分发。
- 文档中记录的候选资源不等于用户已经批准导入。
